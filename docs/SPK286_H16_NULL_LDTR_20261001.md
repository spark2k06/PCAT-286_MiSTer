# SPK286 H16: null LDTR selectors

Date: 2026-10-01. Baseline upstream `fcc67f0`, PCAT `4f92ca0`.

The vendor accepts task-loaded null LDTR values 0000..0003 independently of
RPL and preserves the raw selector in explicit LLDT/SLDT readback. Null paths
do not fetch GDT entry zero. Illegal TI values 0004..0007 remain rejected;
entry zero in a valid LDT remains usable by CS/SS. The composite service's raw
LDTR error now removes RPL, consistent with the executor's existing normalization.

The [contract](../vendor/spk286/docs/PROTECTED_MODE_H16_NULL_LDTR_20261001.md)
distinguishes Intel's selector-field rule from its task-initialization example
and records native 86Box limitations. The
[receipt](../vendor/spk286/docs/REGRESSION_H16_NULL_LDTR_20261001.json) retains
the before/after programs, hashes, observations and directed validation.

Both simulators pass 160 H16 executions in baseline/Max, 1,336 checks each,
and affected service/system/task-LDT banks with P01/P02/P05. Lint, microcode
consistency and portable mapped synthesis pass. Upstream validation also passes
four mutation controls, 352 Python tests and 15,000 real-mode physical captures.
No full regression, physical protected LDTR capture or new hardware boot is claimed.

The final vendor mutation-anchor check exposed an inherited stale RETF allocation
variable name in `audit_far.py`. Its two injection strings now name the current
architectural allocation path, matching upstream. No mutation expectation or CPU
behavior changed; all three anchor tests then pass.

The 86Box SPK executable is rebuilt with P02/P05; private probes have exited.
The normal 50 MHz observer-free configuration, production profiles and fetch-wrap
adaptation are preserved. H02/H05/H17/H19/H20 and PERF01 remain pending. Work
stops after committing this milestone, as requested by the user.
