## Physical timing

The original constraints and physical clock periods are retained. No false
path or multicycle exception was added to hide the new CPU path.

| Corner | Global setup (ns) | Global hold (ns) | CPU setup (ns) |
| --- | ---: | ---: | ---: |
| Slow 100 C | -16.724 | +0.247 | -16.724 |
| Slow -40 C | -17.001 | +0.085 | -17.001 |
| Fast 100 C | +0.581 | +0.126 | +0.581 |
| Fast -40 C | +2.497 | +0.076 | +3.432 |

Recovery, removal and reported pulse-width margins are positive. The two slow
setup corners fail substantially; this is not the selected baseline's small
-0.022 ns residual. Lower OSD MHz choices do not relax the fabric's 20 ns
requirement, and functional simulation does not establish physical safety.

The worst reported path is internal to the CPU:
`prefetch_queue.head_q[2]` → decode/metadata/deadline logic →
`registers.gpr_q[103]`. At Slow -40 C it has 36.278 ns data delay, 31 logic
levels, approximately 19.036 ns cell delay and 17.242 ns routing delay.
The new live metadata/deadline qualification has entered a functional control
cone. It is not a slow SDRAM device path or an HDMI critical path.

The reported chain includes decoder entry selection, metadata and EA/prefix
arithmetic, `effective_base + extra`, `deadline_ready`, `operation_valid`,
executor selection/fault qualification and the GPR data mux. A second cone
also violates setup through CPU request/word-capability qualification,
bridge admission, EMS mapping, cache candidate selection and backend acceptance:
CPU-to-bridge setup is -8.433 ns and the CODE-buffer group reaches -9.932 ns.
Closing only the worst metadata cone would therefore not finish the project.

The next physical milestone must break or shorten that combinational control
dependency while preserving MAX, repeat/event ownership, late metadata updates
and the qualified historical deadline. Registering prepared timing metadata
or separating registered deadline permits from live decode are candidates to
evaluate. A prepared active-body budget must not depend on the following
candidate head, and any registered permit needs correct lookahead, repeat,
event and late-outcome handling. Retained bus classification/admission is a
separate cone to evaluate if it remains critical. None of these follow-ups is
implemented or accepted by this record.

Inherited platform coverage remains explicit: no illegal/unconstrained clocks,
but unconstrained platform I/O and unclocked HPS/peripheral families remain in
the existing scope. SDRAM margins are conditional on the documented device
and board/flight-time budget. Even a positive CPU result would not certify
all external platform interfaces.
